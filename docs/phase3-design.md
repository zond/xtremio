# Phase 3 design — Account, Library, Addons, Settings

Path shorthands: **SC** = `official/stremio-core/src` (the line offsets below were read at rev `7ae100c`; the rev the crate actually builds against is the one `rust/Cargo.toml` names -- currently the `zond/stremio-core` fork -- so a line may have moved. The `serde` attributes are the authority, never the offset.), **WEB** = `…/stremio-core/stremio-core-web/src/model`, **SW** = `official/stremio-web/src`, **X** = `xtremio`.

## 0. Wire conventions that everything below relies on

- Envelope `{"field": <snake name|null>, "action": {...}}` (X `rust/src/core.rs:229-233`). `Action` is `#[serde(tag="action", content="args")]` and every sub-enum (`ActionCtx`, `ActionLoad` with `model`/`args`, …) nests the same way (SC `runtime/msg/action.rs:34-36, 251-252, 286-301`).
- Routing: `field: null` → `model.update` = Ctx **plus every field** (SC `runtime/runtime.rs:57-66`, `stremio-derive/src/lib.rs:83-107`) — the Phase-2 "null Unload clears everything" trap. `field: "ctx"` runs only `Ctx::update` (`lib.rs:54-66`); a Ctx action sent with `field: "board"` is **silently ignored** (`lib.rs:67-80`). Internal messages produced by Ctx effects always go through `model.update` (`runtime.rs:114-118`), so derived models still follow. **Rule: dispatch every `Action::Ctx` with `field: CoreField.ctx`; keep `Unload` per-field.**
- NewState is emitted *before* the effect-produced `CoreEvent`s of the same update (`runtime.rs:79-88`), so when `UserAuthenticated` arrives, a `ctx` pull already reflects the new profile.
- `ctx` JSON = `{profile, notifications, events}` only: `library`, `streams`, `streaming_server_urls`, `search_history`, `status` are `#[serde(skip)]` (SC `models/ctx/ctx.rs:49-78`). Consequences: the Library screen *must* get its own model field, "signing in…" is not observable from state, and the server-URL list needs a projection if ever wanted.
- Casing surprises on the wire: `Event` args are snake_case (`event.rs:14-16`), `AuthRequest.gdpr_consent`, `User.premium_expire/gdpr_consent/_id` (`types/profile/user.rs:86-117`), `LibraryWithFilters.selectable.next_page` (no `rename_all`, `models/library_with_filters.rs:137-142`) vs Discover's `nextPage`, `DescriptorLoadable.transport_url` (`models/common/descriptor_loadable.rs:11-15`) vs `AddonDetails.selected.transportUrl` (`models/addon_details.rs:10-15, 32-38`), `LibraryItem._id/_ctime/_mtime/state.video_id` (`types/library/library_item.rs:17-42, 244-250`).

## 1. ACCOUNT

**Actions (all `field:"ctx"`):**
- Login: `{"action":"Ctx","args":{"action":"Authenticate","args":{"type":"Login","email":E,"password":P,"facebook":false}}}` — `AuthRequest` is `#[serde(tag="type")]`, `facebook` defaults false (SC `types/api/request.rs:185-196`). POSTs `https://api.strem.io/api/login` (`request.rs:150-158`; `unit_tests/ctx/authenticate.rs:75`).
- Signup: `{"type":"Register","email":E,"password":P,"gdpr_consent":{"tos":true,"privacy":true,"marketing":false,"from":"xtremio"}}` (`request.rs:197-201`; `GDPRConsent` `user.rs:38-45`). stremio-web requires ToS + privacy checked, marketing optional, confirms the password client-side (SW `routes/Intro/Intro.js:165-201`).
- Logout: `{"action":"Ctx","args":{"action":"Logout"}}` (`action.rs:38`).
- Post-login/resume housekeeping, what stremio-web dispatches on window focus (SW `App/App.js:146-181`): `PullAddonsFromAPI`, `PullUserFromAPI` with `"args":{}` (`action.rs:82-89`, args object required), `SyncLibraryWithAPI`, `PullNotifications`. Do this once after init when `profile.auth != null`, on `AppLifecycleListener.onResume`, and after `UserAuthenticated`. `PullAddonsFromAPI` while logged out still upgrades bundled official addons (`models/ctx/update_profile.rs:86-133`), so dispatch at startup regardless.

**What happens on login** (`ctx.rs:113-116, 311-391`): status→`Loading` (not serialized), auth request, then concurrently `addonCollectionGet{update:true}` and `datastoreGet{collection:"libraryItem", all:true}`. On `CtxAuthResult`: profile is **replaced** — `auth: Some`, `addons` = API list or `OFFICIAL_ADDONS` with `addons_locked=true` if that fetch failed, **`settings: Settings::default()`** (`update_profile.rs:296-317`); library **replaced** by the API items (anonymous local library discarded, not merged: `update_library.rs:198-217`); streams bucket and server-URL bucket reset (`update_streams.rs:87`, `update_streaming_server_urls.rs:27-36`). Events: `UserAuthenticated{auth_request}`, then `UserAddonsLocked{addons_locked}` / `UserLibraryMissing{library_missing}` or `Error{Other code 7|8}` (`ctx.rs:203-247`, `models/ctx/error.rs:33-79`). Failure: `Error{error, source: UserAuthenticated{auth_request}}` (`ctx.rs:248-254`). Logout: API `logout` + profile/library/streams reset to defaults, `UserLoggedOut{uid}` (`ctx.rs:117-168`, `update_profile.rs:24-32`, `update_library.rs:36-44`).

**Auth state JSON:** `ctx.profile.auth` = `null` | `{"key":"<authKey>","user":{"_id":..,"email":..,"fbId":null,"appleId":null,"avatar":null,"lastModified":..,"dateRegistered":..,"trakt":null,"premium_expire":null,"gdpr_consent":{..}}}` (`types/profile/auth.rs:18-21`; `user.rs:86-117`). Profile is camelCase: `auth, addons, addonsLocked, settings` (`profile.rs:19-31`).

**Error JSON** (`CtxError` `#[serde(tag="type")]`, `error.rs:7-12`): `{"type":"API","message":..,"code":N}` (`types/api/response.rs:27-32`), `{"type":"Env","code":..,"message":..}` (`runtime/env.rs:74-81`), `{"type":"Other","code":1..8,"message":..}` (`error.rs:70-79`). Event: `{"event":"Error","args":{"error":{..},"source":{"event":"UserAuthenticated","args":{"auth_request":{..}}}}}`. Dart `RuntimeCoreEvent` exposes `event`/`args` (X `lib/core/core_events.dart:27-35, 62-72`). Surface: match `Error` whose `source.event == 'UserAuthenticated'` → show `error.message`; clear the local "signing in" spinner on that or `UserAuthenticated` (SW `Intro.js:273-293`).

**UI (Settings → Account section, top):** signed out: email + password, "Sign in" / "Create account" toggle (confirm password, ToS + privacy checkboxes, marketing optional), inline error, spinner while pending, note "Signing in replaces the library on this device with your account's". Signed in: avatar/icon, email, "Sync now" (SyncLibraryWithAPI + PullAddonsFromAPI + PullNotifications), "Log out"; banners for `profile.addonsLocked` and after `UserLibraryMissing{true}`. No model additions; Dart gets `lib/core/state/profile.dart` (`ProfileState`: `auth`, `UserInfo`, `List<AddonDescriptor>`, `addonsLocked`, `ProfileSettings`) and `CoreActions.login/register/logout/pullAddons/pullUser/syncLibrary/pullNotifications`.

## 2. LIBRARY

**State JSON** (`library_with_filters.rs:118-152`, no rename_all): `{"selected":{"request":{...}}|null, "selectable":{"types":[{"type":null|"movie","selected":bool,"request":{...}},…],"sorts":[{"sort":"lastwatched","selected":bool,"request":{...}},…],"next_page":{"request":{...}}|null}, "catalog":[LibraryItem…]}`. **LibraryItem JSON** (`library_item.rs:17-42`, camelCase + `_id/_ctime/_mtime`; state `:215-261`: `lastWatched, timeWatched, timeOffset, overallTimeWatched, timesWatched, flaggedWatched, duration, video_id, watched, noNotif`). `X lib/core/state/continue_watching.dart` already parses this — promote `ContinueWatchingItem` to a shared `LibraryItemView`. Derived: in Continue Watching = `type!="other" && (!removed||temp) && timeOffset>0` (`library_item.rs:52-56`); in Library = `!removed` (`library_with_filters.rs:46-50`); watched = `timesWatched>0` (`:70-72`); progress % (`:58-66`). Played-but-never-added = `removed:true,temp:true`. Optional per-item `notifications` count (WEB `serialize_library.rs:106-122`) → sibling projection (`notificationCounts` array) if wanted.

**Details screen:** `meta_details.libraryItem` always present once meta Ready — bucket or synthesized temp (`meta_details.rs:62, 828-853`; `library_item.rs:176-195`). "In library" = `libraryItem.removed == false`. Bookmark toggle in `_MetaHeader` (X `lib/features/details/meta_details_screen.dart:389-483`) → `AddToLibrary(meta.json)` / `RemoveFromLibrary(id)`; `MetaDetailsState.isInLibrary`.

**Sync after login:** login fetches the whole library, no explicit sync needed. `SyncLibraryWithAPI` (`action.rs:92`): `datastoreMeta` → plan by mtime (`update_library.rs:444-501`) → `LibrarySyncWithAPIPlanned{uid, plan}` then `LibraryItemsPushedToAPI{ids}` / `LibraryItemsPulledFromAPI{ids}` + `UserLibraryMissing{false}`; pulled merge → `LibraryChanged(true)` (`:220-306`). Logged out → `Error{Other code 1}` (`:133-143`). No "syncing" flag in state: transient UI indicator until `LibrarySyncWithAPIPlanned`/`Error`.

**Logged-out:** stremio-web hides Library behind login (SW `routes/Library/Library.js:76`). Core keeps an anonymous library. Recommendation: show local library with "Sign in to sync" banner; warn login replaces it.

**UI plan (`lib/features/library/library_screen.dart`):** AppBar "Library"; filter row reusing Discover's `_TypeSegments/_TypeChips` (≥720 px segmented, else chips; `All` for `null`) and `_OptionMenu` for sort — lift from `discover_screen.dart:140-313` into `lib/widgets/`; `GridView` of poster tiles (LibraryItem → `PosterTile`, progress bar, watched badge); long-press/overflow: Remove, Mark (un)watched, Rewind, Notifications; tap → `MetaDetailsScreen(type, id, videoId: state.video_id)`; `LoadNextPage` when `extentAfter < 600 && next_page != null` (`discover_screen.dart:64-74`); empty state + sign-in CTA. ## 8. Risks and stremio-core surprises

- **Plaintext password in events**: `AuthRequest` derives `Serialize` with the password (`request.rs:185-260`); `UserAuthenticated{auth_request}` and `Error{source}` carry it through the event pump (`core.rs:257-262`) into Dart. Never log `RuntimeCoreEvent.args`; `ctx` JSON carries the auth key — never dump it. Redact real-account fixtures.
